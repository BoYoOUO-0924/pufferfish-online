# 河豚愛生氣 線上版：技術架構與開發步驟

## 1. 目標

- 手機和電腦都能玩，網頁畫面會依螢幕大小自動調整（RWD）
- 朋友間用 **6 碼邀請碼**開房，3～5 人，不需要帳號
- 可以加入電腦玩家，斷線後可以重新連回
- 程式放在私人 GitHub repo，部署到 Cloudflare 免費方案

## 2. 技術選型

| 層 | 技術 | 理由 |
|---|---|---|
| 語言 | TypeScript（前後端共用） | 規則引擎可以在伺服器和前端共用型別 |
| 規則引擎 | 純 TypeScript 模組，不依賴任何平台 | 可以單獨測試，以後要換平台也不用重寫 |
| 測試 | Vitest | 每一條規則都寫測試，連鎖反制特別需要 |
| 伺服器 | Cloudflare Workers + Durable Objects（PartyServer） | 一個房間對應一個 Durable Object，免費、不會休眠 |
| 前端 | Vite + React | 卡牌遊戲用網頁元素做就夠了，不需要遊戲引擎 |
| 動畫 | Motion（原名 Framer Motion） | 發牌、翻牌、出牌、淘汰的動畫 |
| 連線 | PartySocket（WebSocket，內建自動重連） | 搭配 PartyServer 使用 |
| 部署 | 一個 Worker 同時負責網頁和房間伺服器 | 只需要管理一個專案，推送到 GitHub 後自動部署 |

## 3. 專案結構（monorepo）

```
packages/engine/     規則引擎：狀態、動作、結算、電腦玩家 AI，加上測試
packages/protocol/   前端與伺服器之間的訊息格式（型別）
apps/server/         Cloudflare Worker + 房間（Durable Object）
  src/room-core.ts   房間邏輯（不依賴 Cloudflare，可用假時鐘測試）
  src/index.ts       Durable Object 轉接層、建房 API
  scripts/e2e.mjs    端對端測試
apps/web/            React 前端（Vite）
  src/net.ts         連線：自動重連、token、時間校正、延遲量測
  src/components/    等待室、遊戲桌、各種對話框
  public/cards/      卡圖（由 圖片/ 複製，改成英文檔名）
apps/web/            React 前端
assets/              卡圖（由 圖片/ 轉換成 WebP，並提供多種解析度）
docs/                規格文件
```

## 4. 核心設計

### 4.1 伺服器說了算
- 所有洗牌、抽牌、結算都在房間伺服器上執行。玩家的瀏覽器只送出「我想做什麼」，例如「打出這兩張」。
- 洗牌使用 `crypto.getRandomValues`，不能用 `Math.random`。

### 4.2 規則引擎是一個狀態機
```
(遊戲狀態, 玩家動作) → 新的遊戲狀態 + 事件清單
```
- 狀態包含一個「待處理堆疊」，用來記錄等待結算的效果。No way 鏈、Pass 轉移、Chill 放回河豚、漁販選牌、Chef 排序，都是推進這個堆疊的步驟。
- 事件清單（例如「A 抽了 1 張」「B 被淘汰」）用來驅動前端動畫。

### 4.3 每個人只看到自己該看的
- 伺服器會為每位玩家各算一份「視角」：別人的手牌只顯示張數，牌堆只顯示張數。
- 事件也會分開過濾。例如「你抽到了海豹」只送給你，其他人只會收到「A 抽了 1 張」。

### 4.4 計時器
- 回應時間窗、出牌時限、Watch Out 搶按，都用 Durable Object 的 **Alarm** 來計時。
- 計時中的狀態都會存起來，所以房間休眠後醒來也能接著跑。

### 4.5 Watch Out 的公平性
- 前端會定期測量每位玩家的網路延遲。
- 伺服器用「收到按下的時間 − 該玩家的單程延遲」排序，盡量抵銷網路快慢的差異。

### 4.6 斷線重連
- 第一次加入房間時，伺服器會發一組 `playerToken`，存在瀏覽器裡。重新連線時帶著它，就能回到原本的座位。
- 斷線超過 5 秒由電腦代打，座位保留到這局結束；重新連上立刻恢復自己操作。

### 4.7 傳輸格式（摘要）
- **玩家送給伺服器**：`join`、`addBot`、`removeBot`、`start`、`play`（卡片 id 和指定對象）、`respond`（No way 或 Pass）、`placePuffer`（放回河豚的位置）、`fisherChoose`（漁販選牌）、`chefArrange`（Chef 排序）、`chefPick`（Chef 拿牌）、`slap`（Watch Out 搶按）、`ping`
- **伺服器送給玩家**：`view`（自己的完整視角）、`events`（動畫事件）、`error`、`pong`

## 5. 畫面

- **大廳**：建立房間、輸入邀請碼、輸入暱稱。
- **等待室**：顯示座位、加入或移除電腦玩家、複製邀請連結、開始遊戲。
- **遊戲桌**：
  - 對手圍著桌子坐，頭像旁邊顯示手牌數
  - 中間是牌堆和棄牌堆
  - 下方是自己的手牌：多選後出牌，超過 8 張時重疊排列並可以左右滑動
  - 回應時間窗倒數條，旁邊有「No way」「Pass」快捷按鈕
  - 出牌紀錄
- **手機**：直式排版，對手縮成畫面上方的一排頭像。
- **結算畫面**：顯示勝利者和勝利方式，按「再來一局」直接留在同一個房間。

## 6. 開發步驟

| 階段 | 內容 | 完成的樣子 |
|---|---|---|
| M0 | 建立 repo 和 monorepo，設定 Cloudflare 本機開發環境 | `wrangler dev` 可以在本機跑起來 |
| M1 | 規則引擎和完整測試 | 規格書每一條規則都有測試，而且全部通過 |
| M2 | 房間伺服器：邀請碼、加入、開始遊戲、各玩家視角、計時器 | 用測試腳本模擬 3 名玩家，可以打完一局 |
| M3 | 前端基本版：大廳、等待室、遊戲桌，可以實際操作 | 開 3 個瀏覽器分頁可以對戰 |
| M4 | 互動細節：回應時間窗、Watch Out、放回河豚、漁販、Chef | 所有卡片都能在畫面上操作 |
| M5 | 電腦玩家 AI、斷線代打 | 1 個真人加 2 個電腦可以打完一局 |
| M6 | 美術與手感：動畫、音效、手機排版、高解析卡圖 | 在實體手機上測試流暢 |
| M7 | 部署到 Cloudflare，連接 GitHub 自動部署 | 朋友用邀請連結就能遊玩 |

## 7. 需要你準備的東西

1. **高解析卡圖**：目前大約 192×298，建議提供 600×930 以上，或原始繪圖檔。M6 之前提供就可以。
2. **GitHub 私人 repo**：可以由我在本機 `git init`，你再建立 repo 並推上去。
3. **Cloudflare 帳號**：M7 部署時需要你自己登入授權。
4. （選用）音效和背景音樂。沒有的話我會用免費授權的素材，或先不加。

## 8. 開發指令

```bash
npm install                 # 安裝相依套件
npm test                    # 執行所有單元測試（規則引擎 + 房間邏輯）
npm run typecheck           # 型別檢查
npm run dev:server          # 啟動本機伺服器 http://127.0.0.1:8787
npm run dev:web             # 啟動前端 http://localhost:5173（會把 /api、/parties 轉給 8787）
```

本機試玩：同時啟動伺服器和前端，用瀏覽器開 http://localhost:5173 。
同一個瀏覽器的不同分頁會被當成不同玩家（重連用的 token 存在 sessionStorage）。

端對端測試（另開一個終端機，先啟動加速版伺服器）：

```bash
cd apps/server
npx wrangler dev --var BOT_DELAY_SCALE:0.05
node scripts/e2e.mjs
```

### 伺服器 API
- `POST /api/rooms` → `{ code }` 建立房間（6 碼，不含 0/O/1/I/L）
- `GET /api/health` → `{ ok: true }`
- WebSocket `/parties/room/<房號>`：訊息格式見 `packages/protocol/src/index.ts`
